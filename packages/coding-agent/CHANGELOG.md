# Changelog

## [Unreleased]

### Breaking Changes

- Rust SDK: `SessionTree::tree` is a `DeepJson<Vec<Map<String, Value>>>`, which derefs to the list of roots and drops a tree of any depth without overflowing the stack; take the list out with `into_inner()` and drop it with `drop_deep`
- `SqlSessionStorage` with `createTable: false` refuses to start until the session table has a `byte_len` column and a `<table>_parts` table exists; docs/session.md gives the DDL, backfill, and rollback for each dialect. ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- `SqlSessionStorage` refuses table names longer than 57 characters, leaving room for the `<table>_parts` table. ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- An older Oh My Pi can no longer read a SQL session table this version has written until you run the rollback in docs/session.md. ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- Assistant messages in session events, RPC frames and the Go, Python and Rust SDKs now carry the provider's error text in `errorMessage`, omp's shown text (with the request-dump path, the retry hint or a provider explanation) in the new `errorDisplayMessage`, and the delay the failed response's headers asked for in the new `errorRetryAfterMs`, documented in the RPC wire schema. Clients that display an error should show `errorDisplayMessage` when present; `auto_retry_start.errorMessage` and `auto_retry_end.finalError` carry the provider's text ([#17656](https://github.com/can1357/oh-my-pi/pull/17656) by [@sjawhar](https://github.com/sjawhar))
- `omp gc --apply` no longer archives cold sessions by default (`gc.archive` is now off): it no longer moves cold sessions into `archive/sessions`, where the session picker does not list them and an omp without `gc --restore` can neither find nor read them. A configuration that sets `gc.archive` true still enables the phase without `--archive`, and `--archive` still asks for it by name ([#17398](https://github.com/can1357/oh-my-pi/pull/17398) by [@sjawhar](https://github.com/sjawhar))
- `omp gc --apply` no longer reclaims unreferenced blobs by default (`gc.blobs` is now off), so an ordinary maintenance run checkpoints the database WAL files and cannot delete a session's data at all. Deciding that a blob is unreferenced means reading every session that could refer to it, and a session can be created, forked, moved to a sibling or appended to while that reading happens, so the answer describes a tree that no longer exists; a guard strong enough to notice the change refuses whenever anything is writing, which is inert rather than safe. Pass `--blobs`, or set `gc.blobs`, on a machine whose sessions are quiescent ([#17398](https://github.com/can1357/oh-my-pi/pull/17398) by [@sjawhar](https://github.com/sjawhar))
- RPC `prompt_result.error.code` can now be `"session_busy"`: a client built from an older generated Go, Rust or Python SDK reports a parse failure for a busy `prompt_result`, and the Rust SDK's `PromptError.code` field is now the `PromptErrorCode` enum, so Rust code that names `LitCostCap` must use `PromptErrorCode`
- `SqlSessionStorage` with `createTable: false` and `claims: true` on PostgreSQL or MySQL refuses to start until the lease table (`omp_session_leases`, or the `leaseTable` option) exists; docs/session.md gives its DDL.
- `SqlSessionStorage` on PostgreSQL refuses to start when one of its tables has a column it does not declare, a column of another type, a default, a trigger, a rule, row-level security, a constraint other than a key or not-null one, an expression or partial index, or an inheriting table, or when the lease table has no index on `holder` or something else holds the name `<leaseTable>_holder`, whatever `createTable` is; docs/session.md lists what it checks.
- `SqlSessionStorage` on PostgreSQL names its tables `public.<table>`, whatever the login's `search_path` is: a login whose `search_path` puts another schema first, where an older Oh My Pi made and used the tables, now opens on (and makes, with `createTable`) the tables in `public` instead. Move the tables to `public`, or give the login a `search_path` that starts with `public`, before upgrading.
- `SqlSessionStorage` with `claims: true` (the CLI's store) refuses to start on MySQL before 8.0 or MariaDB before 10.3, naming the server's version: an older server cannot bound a lock wait without session state. A store without claims opens there as before. It also refuses, naming the version and the lock form, a server that rejects the lock syntax of the family its version names.
- `SqlSessionStorage` on PostgreSQL that claims sessions or makes its tables (the CLI's store does both) refuses to start on a server in recovery (a hot standby or a read replica), naming that, instead of opening there and failing at its first write.
- `SqlSessionStorage` with `createTable: false` (`OMP_SESSION_SQL_CREATE_TABLE=0`) refuses to start until `<table>_blobs` and `<table>_refs` exist; docs/session.md gives their DDL for each dialect. Start-up on every engine refuses a blob or reference table without its primary key, on PostgreSQL and MySQL one the store's login cannot write, and on PostgreSQL a reference table without an index led by `sha256` (`<table>_rhash`).
- `SqlSessionStorage` on PostgreSQL needs PostgreSQL 16 or later and a client with `reserve()`, which `Bun.SQL` has: on an older server the open fails with error 42704 after 4 attempts, and a client without `reserve()` is refused at open. ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- A session setting set with `SET` on the client given to `SqlSessionStorage`, `SET ROLE` included, no longer applies to the store's transactions on PostgreSQL: each transaction sets `role` and most other session settings back to the value of the login, the database or the server, so a store that relied on `SET ROLE` now runs as the login. Give a setting the store sets back this way with `ALTER ROLE ... SET` or `ALTER DATABASE ... SET`, or as a start parameter of a direct connection. That does not work for five settings, which every transaction sets to the store's own value whatever the login, the database or the connection gives them: `application_name` (`omp-session-store`), `bytea_output` (`hex`), `client_encoding` (`UTF8`), `search_path` (`pg_catalog, pg_temp`) and `synchronous_commit` (`on`). ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- `discoverExtensionPaths()` and `discoverSessionExtensionPaths()` return `{ path, scope }` entries instead of path strings, as do the `deferredPaths` of `loadSessionExtensions()`; `AgentSession.extensionPaths`, `AgentSessionConfig.extensionPaths` and `ToolSession.extensionPaths` list such entries, and each `PreparedExtension` carries the `scope` its extension was found at (`project`, `user`, `explicit` or `inline`)

### Added

- `omp usage --json` now gives each account's `identityKey` (masked by `--redact`) ([#17764](https://github.com/can1357/oh-my-pi/pull/17764) by [@sjawhar](https://github.com/sjawhar))
- Sessions can now be stored in PostgreSQL, MySQL, or SQLite instead of JSONL files: set `session.storage: sql` and point `session.sql.dsnFile` at a file holding the connection string (or set `OMP_SESSION_STORAGE=sql` and `OMP_SESSION_SQL_DSN_FILE`); `--resume`, `--continue`, the session picker, and listing follow the same store, and joining a collab session needs file storage. ([#13416](https://github.com/can1357/oh-my-pi/pull/13416) by [@sjawhar](https://github.com/sjawhar))
- Session storages can implement an optional `readChunks(path, fromByte?)` that streams a transcript's bytes, and an `IndexedSessionStorage` backend (`SessionStorageBackend`, which SDK stores may implement) optional `readChunks` and `writeFullStream` methods, so long sessions resume and rewrite without holding the whole transcript in memory
- An `IndexedSessionStorage` backend (`SessionStorageBackend`) can implement an optional `appendBatch(path, lines, mtimeMs, expectedSize?)` that stores the lines a session queued while one of its appends was in flight in one write; it throws `SessionAppendBatchRolledBackError` when that write stored none of them, and the lines are then appended again one at a time. A backend without it gets one `append` per line, as before
- Session storages can implement an optional `waitForAppendAdmission(signal?)` that resolves once the process may queue more transcript appends, or when `signal` fires; `IndexedSessionStorage` (SQL and Redis session storage) makes it wait while more than 64 MiB of appends are queued across every session of the process (appends made meanwhile still queue, so that is where turns wait, not a bound on the queue), logs a warning once a wait lasts 10 s, and its writers' async `append` resolves only once its line is stored and admission opens
- `omp gc --restore <session id or archive path>` brings an archived session back to its own path with its artifacts, and names what restoring cannot bring back
- Added `--session-id <uuid>` to resume the session with that id or start a new one under it, so a launcher can record the id before the first launch and run the same command every time; while another running omp has that session open it waits as an explicit resume does (up to 35 s on PostgreSQL and MySQL, and on file storage under `OMP_SESSION_EXCLUSIVE=1`) and is then refused before any model call, and it is refused beside `--resume`, `--restore`, `--continue`, `--fork`, `--no-session`, `--from-claude`, `--from-codex` or `--mode acp`
- Added `secrets.maskSessionStore` (off by default): when it is on, the secret values the agent holds (secret-named environment variables except `GIT_CONFIG_KEY_<n>` and `SSH_ASKPASS`, the file that each `*_FILE` variable names except the session transcript that `PI_SESSION_FILE` names, and `secrets.yml` entries) are replaced with a `[REDACTED:<source>:<name>]` marker before a session entry, the title, the draft or a collab replica is written to the session store, before the `/btw` history or a subagent's output files (`agent://<id>`) are written, and before the title and the recaps are kept in `history.db`, while the live session keeps the values. Each session follows its own setting. See [Secrets in stored sessions](../../docs/secrets.md#secrets-in-stored-sessions)
- Under `session.storage: sql`, a second live omp process that opens a session another one holds now moves to a new session id instead of writing the same journal. PostgreSQL, MySQL and MariaDB claim a session with a heartbeated row in `omp_session_leases` that every write checks in its own transaction; a SQLite file with an OS lock. An explicit resume (`--resume`, `--continue`, a picker pick, a session switch) of a held session waits up to 35 s for the holder's lease to expire, so a resume after its holder was killed keeps the id, and that wait holds behind a holder stalled inside a write; the automatic resume claims at open without waiting. One case on MySQL 8 only waits longer: a claim that inserts a new lease row while another store's write to a session it has not claimed is stalled inside its transaction (the write's gap lock also covers other sessions' new rows) waits for that write, at most the resume's 35 s plus the server's `innodb_lock_wait_timeout` (50 s by default), and then counts the session as held. MySQL bounds no `INSERT`'s lock wait without session state; it is safe, because the claim lands only after that write, so no two writers share a session. A heartbeat more than one expiry in the future counts as expired, and a released row whose delete the database gave up on expires instead of being refreshed. Subagent transcripts share their session's lease and follow it to the sibling it moves to. It works through a transaction-mode connection pooler such as PgBouncer: every PostgreSQL heartbeat starts in a read-write transaction, scopes its lock and idle-in-transaction timeouts with `SET LOCAL`, and sends no connection-level setting. `SqlSessionStorage` takes the new `claims`, `leaseTable` and `lease` options.
- `OMP_SESSION_EXCLUSIVE=1` keeps a launcher's recorded session id: a session still held after the wait, a lease taken over or gone, or a file another writer changed or replaced ends the process non-zero, naming the reason, instead of moving to a new id; a `departed` entry is logged and the session opens as it is.
- `OMP_SESSION_SQL_CREATE_TABLE=0` opens SQL session storage without creating its tables, for a login that may not create objects. On PostgreSQL a login without `CREATE` on the schema can also open the store on tables that exist without it: start-up looks for the tables first and makes none that exists.
- Under `session.storage: sql`, each image a session references and cannot draw again is also kept in the session database (`<table>_blobs`, once per SHA-256, outside every session's write fence), and lands before the transcript writes that name it, and only those: a blob write is tried three times, and one that still fails fails those writes, which the session reports, and is tried again by the next. Bytes that do not hash to their reference are never stored, and a row whose bytes do not is rewritten from a machine that holds the right ones. A session opened where the local blob store lacks a blob gets it back from there, with its display copy, and one opened where the table lacks a blob this machine holds writes it back, so a session resumed on another machine keeps its images. `<table>_refs` records which session names which blob, from each transcript write and from each open for writing, so a session written before the table keeps its images when a fork of it is deleted: deleting a session, or a move that replaces one, deletes the blob rows no other session names, without racing a write that adds a reference, and `omp gc --blobs` sweeps the rows no session names. A blob larger than one row takes (`maxBlobBytes`, and MySQL's and MariaDB's `max_allowed_packet` less 1 MiB) is stored in parts. Each stored blob logs its bytes; reads go in batches of at most 16 MiB.
- Added `omp worktree add --lock [--reason <reason>]`, which locks the new worktree as `git worktree add --lock` does; `git worktree add --lock`/`--reason` in bash now keep the clone rewrite, and the `worktree.lockReason` setting locks every worktree a bash `git worktree add` creates through the rewrite with that reason
- `origin: "outside"` on `AgentSession.prompt`, `steer`, `followUp`, `resume`, `sendUserMessage`, `sendCustomMessage` and `promptCustomMessage`, and on extensions' `pi.sendMessage` and `pi.sendUserMessage`, marks input that crossed the session's outer boundary (a person, or a harness or RPC client on their behalf). The TUI, print mode, RPC and ACP set it on what a person or client sends; an extension that relays a person's input sets it itself
- `origin: "outside"` on `pi.sendUserInput`: a bridge that relays a person's typed Send to the root session sets it, and the prompt or skill the text submits, a relayed `/compact` or `/handoff`, and the prompt a built-in submits then end the session's cyber-policy hold, as typed input does (other built-ins read no origin); the extension's own `sendUserInput` leaves it unset and keeps the hold
- Added `live.provider: openai` (or `OMP_LIVE_PROVIDER=openai`, which takes precedence over the setting in the settings files): live voice (`/live`, RPC `live_start`/`live_connect`, extension `startLive`) runs GPT-Live on OpenAI's API, billed to the `openai` provider's key (a stored key, `apiKey` in `models.yml`, else `OPENAI_API_KEY`) at its `baseUrl` (default `https://api.openai.com/v1`), instead of the ChatGPT (Codex) subscription. Since GPT-Live's delegation carries no text, a delegation's turn is the user's transcribed words before its `offset_ms`, labelled as speech-to-text; it waits for the user's transcript to reach that offset (at most 1 s) and is never dropped. `live.provider: codex` stays the default
- The SDK exports `applyToolResultPrunes` and `applyEntryPatches`, so a caller of `loadSessionFile` or `loadEntriesFromFile` can apply a session's prune and patch records to the raw entries it reads
- In RPC mode, `/live on`, `/live off` and `/live status` typed as a `prompt`, or sent through an extension's `sendUserInput` (a chat bridge's), run at once, even during a turn, drive the same live session as `live_start`/`live_stop`, and answer in one `command_output` line (`sendUserInput` also returns it as `output`); the checks `live_start` makes (dictation, a session change or shutdown) now apply to both. A `prompt`'s `/live on` connects in the background, so the input queue stays free while the call connects, and `/live off` or `abort` meanwhile stops it. ACP, print mode and subagents answer `/live` as not available
- `SessionManager.create()` takes the `{ suppressBreadcrumb }` option `SessionManager.open()` takes, for a session that writes no terminal breadcrumb
- `task.namedModelFallback` (default `true`): set it to `false` and a subagent whose model is named by selector (agent `model`, `task.agentModelOverrides`, SDK `modelOverride`) runs only on the models it names, in order, and fails instead of substituting the parent's model on missing credentials or moving to a `retry.fallbackChains`, context promotion or prewalk model; role aliases such as `@task` keep their role's chain
- `retry.fallbackNotice` (default `false`): with it on, a session whose model changed through a retry fallback, or that returned to its primary, gets one hidden notice naming the model now serving it and why, once a turn has been served on it; a running session sees it on its next model request

### Changed

- Secret obfuscation and the stream redaction of `omp stream` and `/record` no longer take `GIT_CONFIG_KEY_<n>` and `SSH_ASKPASS` from the environment: they hold git configuration key names and an askpass program path, not secrets, so text that holds those common strings reaches the model provider, stream viewers and recordings unchanged
- `async.maxJobs` now sets the cap on background jobs running at once in a session and its subagents without the fixed 100 ceiling, and `0` means no limit; the default stays 100
- A session left working in a detached tmux pane no longer spends a slice of a core animating a screen nobody can see: the status line drops to one frame a second and the terminal-title spinner pauses until a client is watching again ([#17404](https://github.com/can1357/oh-my-pi/pull/17404) by [@sjawhar](https://github.com/sjawhar))
- When saving pruned tool output fails, the pruning now stays applied in the live context, and the session file catches up on the next successful save.
- Recovered retries, compaction stamps and elide passes append a small record instead of rewriting the whole session file, so they stay fast on long sessions; when an entry they change has a line of 4 MiB or more, the file is still rewritten, so a collab guest can fetch that entry. With session-store masking on, each record is masked by the rules of the entry it changes.
- Discarding a failed assistant turn no longer rewrites the whole session file, so it no longer slows down as a session grows; the discarded turn stays in the file off the active branch and still counts toward usage totals
- Long compacted sessions spend less time in prune and shake between turns
- A resumed session keeps in memory only the entries since its latest compaction: older message bodies, tool results and summaries wait in a temporary file and are read back when something asks for them, so long sessions take far less memory
- A resumed session keeps less of each older entry in memory: an older message keeps only the few small fields every turn reads, and older tool start markers and every to-do list edit except the one the list restores from wait in the temporary file with the older bodies, so memory grows far less as a session gets longer
- Hindsight auto-retain, the pending-tool-call warning on resume and the exit record read only recent messages on each turn instead of the whole history
- `.jsonl.gz` subagent transcripts in exports are decompressed as they are read instead of all at once
- `omp session pack` and `omp session unpack` stream the transcript and its artifacts instead of reading them whole, so moving a long session between machines no longer holds copies of it in memory
- A rate limit now waits on the same model, retrying it after the wait the provider states, before it walks `retry.fallbackChains`, and never moves a session whose context, as the status line shows it (a prompt no request has answered yet included), is larger than the new `retry.rateLimitFallbackMaxContextTokens` (default 100,000 tokens); a rate limit that cuts off an answer already on screen waits the same way and then continues that answer on the same model, never walking the chain; overloads and server errors still walk the chain at once
- A parked task subagent is revived from the spawn spec its spawn wrote to its own transcript, so it keeps less in memory while parked; when its transcript holds no spec, or holds one its park never wrote (a seance consult, a transcript edited or rolled back), it is revived the way a subagent restored from disk is
- A turn waits before its next model request or tool result while the session storage (such as SQL storage) has too many transcript appends queued, so a backlogged database slows the turn instead of growing memory
- A session on the default agent directory now opens the shared skill-description cache (skill-descriptions.db) only at its first prompt that lists a skill. Such a session that lists none, or ends before it renders one, never opens it. A cache that cannot be opened is still logged once, now at that first prompt. An SDK session rooted in another agent directory still opens its own cache when it is created
- A session that moves to a new id because another writer holds its file is now a fork: its header names the old id as `parentSession` and no `continuationOf`, and an exact `--resume <id>` opens that id without following a continuation.
- `SqlSessionStorage` start-up on PostgreSQL takes the database-wide start-up lock only when a table is missing, and then once, making every missing table (and the lease table's index) in one round trip; on tables that exist it sends no `CREATE` at all. Many stores starting at once on a busy database no longer queue on that lock.
- The `voice` that RPC `live_start`/`live_connect` (and `RpcClient.liveStart()`/`liveConnect()`, and the Python SDK's `live_start()`, which returns `None`) and extension `startLive` return is optional: with `live.provider: openai` it is absent, since GPT-Live gets no voice from omp, and a `voice` passed in is ignored
- `loadExtensions()`, `importExtensionModule()`, and the `preloadedExtensionPaths` of `CreateAgentSessionOptions` and of `ExecutorOptions`, also take `{ path, scope }` entries; a bare path is read as `explicit`, and so is a prepared extension without a `scope` given to `bindPreparedExtensions()`, in `CreateAgentSessionOptions.preloadedPreparedExtensions` or `.preloadedExtensions`, or in `ExecutorOptions.preloadedPreparedExtensions`
- `retain`, the memory instructions and the Mnemopi fact extractor now ask for a memory as a record of what was said or done, by whom, when, why and where to find it, not as a bare rule or command, so a later session can weigh a recalled memory instead of obeying it. The extractor also treats its input as text to extract from, not as a request to answer
- Resuming a session whose provider was removed now walks that model's exact `retry.fallbackChains` key to the same model under its new provider, or refuses with a message that names `--model` and the key to add; it no longer silently substitutes the default model
- A classifier refusal (`stopDetails.type` `refusal` or `sensitive`, of any category) is now sent again, unchanged, to the model that refused it, up to two times for each model and inside `retry.maxRetries`, before turn recovery walks `retry.fallbackChains`; with no chain, the turn ends only after those retries. An advisor resends a refused batch to its model the same two times before it strips the primary's reasoning or switches models; an OpenAI `cyber_policy` refusal is still never sent again.

### Fixed

- The Hindsight retain outbox now sends the memories of each tag set in the order they were queued. It ordered them by file modification time alone, so memories written within one tick of the filesystem's clock (most often the items of one call) went out in the directory's listing order, which differs from one filesystem to the next. Each queued memory now records a sequence one past the highest pending one's; memories an older release queued have none, and go first, by modification time, as before
- An automatic retry no longer ends twice when the next reply finishes while the retry's outcome is still being saved (as on a busy SQL session store): it published two `auto_retry_end` events for one failed request and saved the outcome on the failed attempt's entry a second time. A retry that starts in that window keeps its own state: the earlier retry's end no longer reports it as finished (`isRetrying` false while it runs) or clears its record of the models a refusal already left, which let the refusal walk ask a model it had left
- The compaction live-context release test no longer fails about once in 460 runs under parallel load (once in 380 with 16 at a time): its probe read "no string of this key is in a heap snapshot" as "no holder keeps this key", and a snapshot shows a live string's text only while no other live string of its length hashes to the same 24 bits, and then only for the first of the two it writes (Bun's `BunV8HeapSnapshotBuilder::addString` keys its string table on `(hash, length)` and keeps the text first given under that key). The probe now says how many of each holder's keys the snapshot showed, and the precondition reads a key it could not show as one it cannot judge rather than one no holder keeps
- A stop while a live call connects (`/live off`, RPC `abort` or `live_stop`) now cancels the pending session request at once, so the start answers `The live call was stopped while it connected` instead of waiting for the server; and the call ends clean, as an open call's stop does, instead of ending with `Live transport is not connected` (nothing is sent to a call that is not up)
- ACP clients are no longer offered `/live`, which ACP answers as not available
- SQL session storage on MariaDB 11.6.2 or later no longer fails a write whose locking read or write meets a row another transaction changed after the write's read view was made, at its first plain read, not at `BEGIN` (error 1020, `Record has changed since last read`, raised under MariaDB's default `innodb_snapshot_isolation`): MariaDB rolls such a transaction back as it does a deadlock victim, and the store now runs it again the same way, up to five attempts. A session write that waited for a delete of the image it names, for one, then lands the image again instead of failing.
- `omp --no-session` under `session.storage: sql` no longer opens the session database at start-up: it opens it when something in the run first uses the store (a subagent's transcript), so a database that is down, refuses the connection or holds the session table locked neither ends nor stalls a run that keeps no session. The configuration is still checked at start-up and refuses as before; the database's own refusal now comes at that first use, and the next use tries the database again. `omp --mode acp --no-session` now keeps each `session/new` session in memory, as the launch's own session is, so it writes nothing to the store; before, it wrote every new session. Under `--no-session` the ACP agent also neither advertises nor serves `session/list`, `session/load`, `session/resume` and `session/fork`, nor serves omp's own listing methods `_omp/sessions/listAll`, `_omp/projects/list` and `_omp/chats/byCwd`, which read the store: each is refused with error -32601, `<method> requires session persistence; omp was started with --no-session`, before the store is read, and a `session/load` or `session/resume` of a session `session/new` made earlier in the same run is refused too; the agent advertises only `session/close`. `SqlSessionStorage.createOnFirstUse` builds such a store.
- Where the shell decodes program output (Windows with a legacy code page), output that ends inside a character no longer comes after the next command's output when the program leaves a process holding its output open. The cost: that character comes out at once, as the code page reads its start while the output is still read as UTF-8 (日 cut short is `鏃` under code page 936), or as U+FFFD when the output was already read from the code page; the rest of it that the left-running process writes later is dropped: the bytes that finish it as UTF-8, or else the one byte after a lone double-byte lead when the code page reads the two as one character, which can be ASCII `@` through `~` in code pages 932, 936 and 950 and an ASCII letter in 949
- Deleting a project's daemon runtime directory while its broker runs no longer lets a second broker take the same project: the broker now locks `<scope>.broker.lock` beside that directory in `~/.omp/run/daemons/`. These files are empty, one for each project scope ever used, and are never removed. A broker also steps back while a broker of an older omp version holds the project, though not when both start at the same moment.
- A subagent launched while the session store refuses writes (a full or quota-exceeded disk, a SQL store that is down, busy or read-only, including PostgreSQL behind PgBouncer 1.22.0 to 1.26.1) now starts at once: its transcript stays in memory and is written once the store accepts writes, as the main session's is. Behind PgBouncer, a write that meets its login-retry error for a login the server rejected (a wrong password, for one) also reads as a store that is down; the writes waiting when the server rejects the login get the server's own error instead (28P01 for a wrong password), which is no refusal, so a close that meets it is not kept. A fork (`--fork`, a subagent's seance fork) and a switch to a new session path start the same way. `/tan` still fails while its parent session holds a write the store refused, because it writes and flushes the parent before it forks. Resuming a session that moved away and unpacking a session whose local copy diverged still fail, as their notice cannot be written, and drop the fork. A session whose close the store refused for an outage keeps its transcript until a later write lands on the same store, and then releases it; a close the store refused for permission is not kept, and the entries it could not write are lost. A session whose directory the store refuses to make now starts and warns instead of failing at start. A session the store refuses for permission (`EACCES`, `EPERM`, a read-only file system or SQLite database) also starts, but only its own writes try again
- On a session store that sessions share, one session's failed write no longer fails another session's flush or close once a later write has landed on the store
- A disposed session whose final close fails now releases its in-memory transcript, but for the entries a close refused for an outage holds for the later send, and lifts its account pools, as one whose close lands does; before, a parked subagent whose close failed kept both. - A cancelled `edit` no longer starts a write after the cancel. Before, an edit cancelled while it resolved an internal-URL target, recovered a missing path, or wrote the files of a multi-file edit went on to write them, even though the call was already reported as aborted (for example, a subagent cancelled with its edit pending). Now the call ends as aborted, and its message names what the call's earlier writes changed (a move by its source and destination), also when the cancelled edit closes an LSP batch. A write already under way when the cancel arrives is not stopped by the edit engine; it sees the cancel only where it checks for one itself, and the call ends as that write's result. Through an ACP client, a cancel seen just before the client is asked to write fails the write, and nothing is written; otherwise the change lands, and the write succeeds. A failed write ends the call as a failed write (`write_failed`) that names no earlier file, or, when the call closes an LSP batch whose flush then fails too, as that flush's error; a write that succeeds is named in the cancel message, or, as the call's last write, the call succeeds.
- An `edit` written through an ACP client and stopped by the call's abort before the client was asked to write now reports "Operation aborted". Before, it was a failed write (`write_failed`) with an empty message: the bridge threw the signal's own reason, an abort `DOMException`, and the native edit engine's conversion of a writer's rejection gives no text for it.
- A change that `edit` has already made (on disk, through an ACP client, or as a delete or a move) is now reported as made when the call's abort arrives after it, and the language servers are told of it. Before, the abort stopped the LSP notice of the change, and the edit ended as a failed write (`write_failed`, "Operation aborted") although the file had changed: an agent could apply the change again, and the servers kept a stale view of the file. The notice of a made change (from `write` too) is bounded only by its own 2 s timeout, so an `edit` aborted after its change can wait up to that long when a language server stops reading.
- An `lsp` rename or code action whose workspace edit has already changed files is now reported as applied when the call's abort arrives after it, and the language servers are told of the change. Before, the abort stopped the refresh of the open documents, so the call ended as aborted although the files had changed, and the servers were not told. A call already aborted when the edit would start changes nothing; before, it applied the edit and then reported the abort. Without an abort, bringing the open documents up to the new text waits for the server as before; once the call is aborted, all the steps still to finish share one bound of 2 s from the abort, so a language server that stops reading can add up to 2 s before the notice's 2 s. For `rename` and code actions the call's deadline counts as the abort: with `timeout: 5`, such a call can take up to 9 s. Each open file is refreshed on its own: a step that fails no longer fails a call whose edit has run, and no longer skips the other files; the result names it. A workspace edit that fails after it has changed files (the action's own, or one the server applies for a command) now names those changes, with or without an abort, and the servers are told of them; before, the error, the abort or the command's result left them out. A recursive delete in a workspace edit now lists the tree first, following no symbolic link, and the call's abort or deadline stops it while it lists, before it removes anything, if the edit has changed nothing yet (so an aborted edit never stops halfway); a read through a directory swapped for a link while it lists (the directory itself, its parent, or one further up swapped for a link to another directory) is dropped, so the files behind the link are not named. A directory further up moved away and replaced by a link to its new place, or a swap undone before the check, is not caught; then the names are still paths under the tree, and nothing outside it is removed. Bun's own recursive `rm` then removes the tree; on Linux a directory swapped for a link while it runs is removed as the link. In gVisor, `openat` with `O_DIRECTORY|O_NOFOLLOW` follows a link (google/gvisor#14786), so there Bun's `rm` can follow such a link, as it could before this change. When it stops partway (at a directory the user cannot write, say), it stops at its first failure, and the error names the first 20 listed paths that are gone and counts the rest; a path added to the tree while it ran is not named, and may have been removed. Past the call's deadline, such an error asks for the files to be read before any retry instead of suggesting one.
